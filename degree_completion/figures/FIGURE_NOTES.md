## Figure 1 — Initial model comparison

**Files:** `figure1_initial_model_comparison.png` / `.svg`

### 1. Source notebook and exact cells
`this work/04.2_baseline_comparison.ipynb`:
- Cell 9 — `baseline_results`: Selected engineered-feature pipeline, Majority-class, Stratified-random.
- Cell 10 — adds `TF-IDF + LogReg`.
- Cell 33 — `length_vs_others`: adds `word_count` alone (re-states the other two for comparison).

### 2. Data and metric definitions
- **Metric:** held-out PR-AUC (average precision), chosen over accuracy/ROC-AUC because the positive
  class (`is_convincing`) is rare (~16–20% depending on the split).
- **Selected engineered-feature pipeline:** XGBoost + SMOTE on 229 columns (`trusted+untrusted`
  feature set — includes 187 PCA embedding components), the architecture selected via a prior
  3-classifier × 3-resampler × 3-feature-variant grid in `04.1_model_training.ipynb`.
- **TF-IDF + Logistic Regression:** `TfidfVectorizer(max_features=5000, min_df=2)` on
  `cleaned_final_comment`, no engineered features at all.
- **Word count alone:** a single scaled feature (`word_count`), Logistic Regression.
- **No-skill baseline:** `DummyClassifier(strategy='most_frequent')`'s PR-AUC, which equals the
  test-fold's own positive rate by construction — the methodologically correct no-skill reference
  for PR-AUC (not 0.5, and not the whole-dataset positive rate).

### 3. Exact values used
| Model | PR-AUC |
|---|---|
| Selected engineered-feature pipeline | 0.3848 |
| TF-IDF + Logistic Regression | 0.5119 |
| Word count alone | 0.5256 |
| No-skill baseline (majority class) | 0.2031 |

(Stratified-random, 0.2013, also appears in the notebook but is omitted from the figure as a
redundant second no-skill-style reference — majority-class is the more standard one to show.)

### 4. Experimental population and evaluation split
Full dataset (3,971 comments, 401 threads). Thread-grouped `GroupShuffleSplit` (80/20, `random_state=42`):
train 3,262 comments / 320 threads, **test 709 comments / 81 threads** — zero thread overlap,
verified by assertion in the notebook. All three models (and both no-skill baselines) are evaluated
on the identical 709-comment test fold.

### 5. Meaning of any error bars
None shown. All three values are single-split point estimates (no bootstrap CI or repeated-split
averaging was computed for this specific three-way comparison in `04.2`). This is a genuine
limitation — `04.2` cells 12–14 show the Selected-pipeline's point estimate (0.3848) sits about 1 SD
above its own order-robust mean (0.3676±0.0182) computed elsewhere in the notebook — but no
corresponding order-robust or bootstrap figure exists for all three models side by side on this
specific comparison, so none is fabricated here. If asked, say "point estimates on a single
709-comment test fold," not "the only true value."

### 6. Scientific caveats
- This is a **single train/test split**; most pairwise PR-AUC differences in this project have
  overlapping bootstrap confidence intervals. The word-count-vs-engineered-pipeline gap specifically
  is the one comparison in the broader project with the least overlap (see `PRESENTATION_STORYLINE.md`
  Section 3), but that CI check was computed on a word-count-fix comparison (0.3848→0.4922, not shown
  in this figure), not on the raw three-way comparison plotted here.
- The engineered pipeline includes `word_count`-adjacent information only indirectly (via other
  engineered signals); it was *not* originally designed with `word_count` as a feature (that fix is
  a separate, later result — Section 3c of the storyline, not part of this figure).
- Do not read this figure as "engineered features are useless" — only that the specific selected
  229-feature pipeline, as originally built, underperforms two much simpler baselines on this test
  fold, which is itself what motivated the length-confound investigation.

### 7. Suggested one-sentence takeaway
"On this task, how much someone wrote predicted persuasion better than our carefully engineered
feature pipeline did — which is what led us to look at comment length directly."

### 8. Suggested speaker notes (~25–30 seconds)
"We started with a fairly elaborate feature pipeline — 229 engineered features, including text
embeddings, sentiment, tone, and more — selected through a systematic model-comparison grid. Its
held-out PR-AUC was 0.38. As a sanity check, we tried something much simpler: TF-IDF with logistic
regression, no engineered features at all. It scored 0.51 — better. That was surprising enough that
we dug into *why*, and the answer turned out to be almost embarrassingly simple: a lot of what
TF-IDF was picking up was just how *long* the comment was. So we tried the single feature
`word_count` alone — and it scored even higher, 0.53. That's the finding that reframed the rest of
this project: comment length is a dominant signal, and the central question became whether anything
*beyond* length also matters."

## Figure 2 — Incremental value of rhetorical strategies

**Files:** `figure2_strategy_incremental_value.png` / `.svg`

### 1. Source notebook and exact cells
`this work/06_strategy_ablation.ipynb`, cell 17 (`headline_df`), built on the order-robust evaluator
defined in cells 10–15 and the column-order sensitivity check in cells 11–14.

### 2. Data and metric definitions
- **Metric:** held-out PR-AUC, **mean ± SD across 8 random orderings** of the same fixed column set
  (architecture: `XGB (over)` + `SMOTE`, the same pipeline selected in `04.1`/`04.2`).
- **Engineered-feature model (no rhetorical scores):** `X`, 229 columns (`trusted+untrusted`), same
  feature set as Figure 1's "Selected engineered-feature pipeline" but now evaluated on the
  LLM-scored subset and averaged over column orderings rather than as a single-split point estimate.
- **+ 8 rhetorical-strategy scores:** the same 229 columns plus the 8 LLM-scored strategy columns
  (`justification, concession, evidence, refutation, personal_narrative, call_to_action,
  simplification, question_asking`), 237 columns total.
- **Strategy scores only:** the 8 strategy-score columns alone, nothing else.
- **No-skill baseline:** test-fold positive rate on this notebook's own split of the scored subset
  (0.2382) — different from Figure 1's 0.2031, because the scored subset has a different composition
  and a different split than the full dataset (see population note below).

### 3. Exact values used
| Model | PR-AUC mean | PR-AUC SD |
|---|---|---|
| Engineered-feature model (no rhetorical scores) | 0.4467 | 0.0196 |
| + 8 rhetorical-strategy scores | 0.5202 | 0.0177 |
| Rhetorical-strategy scores only | 0.3538 | 0.0079 |
| No-skill baseline (scored subset) | 0.2382 | — |

### 4. Experimental population and evaluation split
**LLM-scored subset**, not the full dataset: 2,753 comments (comments ≥30 words, or any length if
convincing — the population `05_rhetorical_scoring.ipynb` actually scored), 400 threads.
Thread-grouped split: train 2,161 comments / 320 threads, **test 592 comments / 80 threads**.

### 5. Meaning of any error bars
**Error bars are ± 1 SD across 8 random orderings of the same feature columns, fitting the identical
fixed `XGB (over)` + `SMOTE` architecture on the same train/test split each time — only the order the
columns are passed in changes.** `06` cells 11–14 document that this specific pipeline is sensitive
to column order (reshuffling order alone swings PR-AUC by up to 0.0422 on an identical 237-column
set), root-caused to XGBoost's deterministic tie-breaking among near-equal split gains on correlated
features. **These are explicitly NOT bootstrap confidence intervals and NOT a result of repeated
train/test sampling** — the train/test split itself is fixed throughout; only column order varies.
State this plainly if asked what the error bars mean.

### 6. Scientific caveats
- The three bars are evaluated on the **scored subset**, not the full 3,971-comment dataset — its
  own no-skill baseline (0.2382) is not directly comparable to Figure 1's (0.2031).
- The gain from adding strategy scores (+0.0735) clears the combined order-noise band of the two
  means being compared, so it is not an artifact of column-order sensitivity — but it is still a
  single dataset's result, not independently replicated at this stage (replication is addressed in
  the project's WA external-validation analysis, not part of these first three figures).
- Strategy scores are LLM-generated measurements on a 1–5 rubric, not direct observations of a
  mental state or ground-truth human annotations (see `05_rhetorical_scoring.ipynb`).
- "Strategy scores only" (0.3538) sits between the no-skill baseline and the full model — real
  standalone signal, but strategy scores are not a replacement for the engineered feature set; they
  add more value as a supplement than they carry alone.

### 7. Suggested one-sentence takeaway
"Adding eight LLM-scored rhetorical-strategy measures to the existing feature set produces a real,
order-robust improvement in predicting persuasive comments."

### 8. Suggested speaker notes (~30–35 seconds)
"Length isn't the whole story, so we asked: does *how* an argument is made add anything on top of
how much was written? We scored every comment on eight rhetorical strategies — things like
refutation, justification, use of evidence — using an LLM, on a 1-to-5 scale. Adding those eight
scores to the existing engineered feature set lifted PR-AUC from 0.45 to 0.52. The error bars here
aren't the usual confidence interval — they come from a quirk we found in this specific model: with
over 200 correlated columns, just the *order* you feed them in to XGBoost shifts the score by up to
0.04, enough to matter. So every number in this part of the analysis is an average over several
different column orderings, and this gain comfortably survives that averaging — it's a real,
order-robust effect, not noise."

## Figure 3 — Rhetorical-strategy gain under length matching

**Files:** `figure3_strategy_gain_length_matching.png` / `.svg`

### 1. Source notebook and exact cells
`this work/06_strategy_ablation.ipynb`:
- Cell 31 (markdown) — explains why this notebook re-runs its own length-matching rather than
  reusing `04.3`'s sample.
- Cell 32 — builds the strict 1:1 length-matched sample **within the 2,753-row scored population**
  (decile-binning `word_count`, same procedure as `04.3`, but applied to a different starting
  population).
- Cell 34–35 — `length_benchmark_df`: evaluates the engineered model with/without the 8 strategy
  scores on both the full scored population and the length-matched sample.

### 2. Data and metric definitions
- **Strategy-score gain** = PR-AUC(engineered features + 8 strategy scores) − PR-AUC(engineered
  features alone), both arms using the `trusted`-only (229-minus-8, i.e. the same `X.columns` used
  pre-strategy) feature baseline, each an order-robust mean over 8 column orderings.
- **Full scored population:** all 2,753 LLM-scored comments, test-fold positive rate 0.2382.
- **Length-matched sample:** a strict 1:1 decile-match of non-convincing to convincing comments'
  `word_count`, built **within** the 2,753-row scored population (not from the full 3,971-row
  dataset — see caveats), 1,235 comments, test-fold positive rate 0.5132. `word_count` correlation
  with the outcome drops from r=0.2882 (unmatched) to r=0.0608 (matched) — matching worked.
- **Retention %** = (gain on length-matched sample) / (gain on full population) × 100.

### 3. Exact values used
| Population | n | Strategy-score gain (PR-AUC) |
|---|---|---|
| Full scored population | 2,753 | 0.0664 |
| Length-matched (within scored population) | 1,235 | 0.0557 |

Retention: 0.0557 / 0.0664 = 83.9%, reported on the figure as **84%**.

### 4. Experimental population and evaluation split
Both rows use a **fresh thread-grouped 80/20 split specific to that row's sample** (not the same
split as Figure 2 — matching changes the row composition, so the split is rebuilt). Both arms are
order-robust means over 8 column orderings on that row's own split.

### 5. Meaning of any error bars
**None shown, intentionally.** The notebook reports an order-robust SD for each of the four
underlying PR-AUC arms (with/without strategy scores × full/matched population — `06` cell 35), but
does **not** compute a corresponding uncertainty estimate for the *gain* (the difference of two
means) or for the *retention percentage* (a ratio of two gains). Showing error bars on this chart
would require propagating or re-deriving an uncertainty figure that doesn't exist in the notebook —
that would be inventing a precision estimate, so none is shown. If asked for the uncertainty on the
84% figure specifically: it isn't computed anywhere in this project; say so rather than guessing.

### 6. Scientific caveats
- **This is a comparison of incremental PR-AUC *gain*, not of raw PR-AUC across the two
  populations** — the full population and the length-matched sample have very different positive
  rates (23.8% vs. 51.3%), so their raw PR-AUC values are not on a comparable scale; only the
  *within-population* gain (with-strategy minus without-strategy, holding the population fixed) is
  compared across the two rows.
- **This length-matched sample is a separate, differently-built construction from
  `04.3_length_controlled_analysis.ipynb`'s own strict 1:1 match.** `04.3`'s sample is built from the
  *full* 3,971-row dataset; `06`'s sample (shown here) is built from the *2,753-row LLM-scored
  subset* only, because many of `04.3`'s matched non-convincing rows fall under the 30-word scoring
  floor and have no strategy score (`06` cell 31). Per the task that produced this figure, the two
  are **not** combined into one chart or retention statistic here. (Separately resolved 2026-10-14:
  `06`'s own narrative text, cell 36, mis-cites a "25%" figure from `04.3` that is actually a
  different quantity on a different sample — see `PRESENTATION_STORYLINE.md` Section 7's
  verification checklist. Not reproduced on this figure or anywhere in these notes.)
- Length matching substantially reduces sample size (2,753 → 1,235) and therefore statistical power;
  the 84% retention figure is itself a point estimate, not a significance-tested claim.
- "The gain survives length matching" supports the existence of additional predictive signal beyond
  length; it does not prove complete independence from length, nor does it establish that rhetorical
  strategies *cause* persuasion (predictive association only).

### 7. Suggested one-sentence takeaway
"Once comment length is controlled for, the predictive gain from rhetorical-strategy scores barely
shrinks — unlike most other signal in this project, it isn't just another proxy for length."

### 8. Suggested speaker notes (~30–40 seconds)
"Showing that strategies help isn't enough — we already know length dominates everything else, so
the real question is whether the strategy gain is *also* just a length proxy. We built a strict
length-matched sample: for every convincing comment, a non-convincing comment of near-identical
length, within the same scored population used in the last slide. That collapses most models' skill
— length was doing most of the work. But the specific *gain* from adding the eight strategy
scores — the improvement they add on top of the existing features — only drops from 0.066 to 0.056,
about 84% retained. That's the strongest piece of evidence in this project that the strategy scores
are capturing something about *how* an argument is made, not simply re-deriving *how much* was
written. I want to flag one thing precisely: this is a different length-matched sample from one used
elsewhere in this project's own analysis — built from the smaller, LLM-scored subset specifically, so
that every row still has a strategy score — and I'm not merging the two here."
